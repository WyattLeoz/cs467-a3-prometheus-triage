### What did you do?

Summary
Upgrading to kube-prometheus-stack 78.5.0 on a single-node k3s cluster (deployed via ArgoCD) creates the Prometheus custom resource, but no Prometheus StatefulSet or Prometheus pod is created.

Environment
- Kubernetes distro: k3s (single node)
- Deployment method: ArgoCD Application
- Chart: kube-prometheus-stack
- Problematic chart version: 78.5.0
- Working chart version: 78.4.0
- Namespace: observability

What I observe on 78.5.0
- Prometheus Operator is running
- kube-state-metrics is running
- node-exporter is running
- ServiceMonitors exist
- Prometheus CR exists
- No Prometheus StatefulSet is created
- No Prometheus pod is created
- Prometheus CR shows DESIRED=1, READY empty
- Prometheus CR has no status section
- No Events on the Prometheus resource
- No reconcile errors in operator logs related to this resource

Relevant outputs on 78.5.0
- kubectl -n observability get prometheus:
  - NAME: prometheus-kube-prometheus-prometheus
  - VERSION: v3.7.2
  - DESIRED: 1
  - READY: empty
- kubectl -n observability get sts:
  - no Prometheus StatefulSet present
- kubectl -n observability describe prometheus prometheus-kube-prometheus-prometheus:
  - Events: none

Behavior after downgrade
After downgrading chart version from 78.5.0 to 78.4.0:
- Prometheus StatefulSet is created
- Prometheus pod is created and running
- Prometheus CR becomes healthy:
  - READY=1
  - RECONCILED=True
  - AVAILABLE=True
- Prometheus version shown becomes v3.7.1

Expected behavior
On 78.5.0, Prometheus Operator should reconcile the Prometheus CR into a StatefulSet and running Prometheus pod, as happens on 78.4.0.

Actual behavior
On 78.5.0, reconciliation appears incomplete or stalled: CR exists, but no StatefulSet/pod is created and CR readiness/status does not progress.

Reproduction steps
1. Deploy kube-prometheus-stack chart version 78.5.0 on k3s single-node cluster.
2. Confirm operator, kube-state-metrics, and node-exporter are running.
3. Confirm Prometheus CR exists.
4. Check for Prometheus StatefulSet and pod.
5. Observe missing StatefulSet/pod and missing CR readiness/status progression.
6. Downgrade to 78.4.0 and observe issue disappears.

Additional notes
- I also saw TLS handshake errors in operator logs, but this seems unrelated to the missing Prometheus StatefulSet in this case.
- Webhook failure policy observed was Ignore for related validators.
